# Startup Prototypes · 一人创业实验室

**三份业务数据，三个可以动手试的产品原型。** 找出一笔少结的退款、一次客服升级造成的答复退步，或者一条产线反复漏检的样本。

三个工具共用一个本地浏览器工作台。自带虚构样例，需要 Node.js 22+，无需安装依赖或申请 API Key。

## 先跑一次看看

```sh
git clone https://github.com/geokyding/startup-prototypes.git
cd startup-prototypes
node server.mjs
```

打开 [本地工作台](http://127.0.0.1:4173)，选择一个工具，再点 **运行分析**。样例会自动载入，也可以替换成自己的 JSON 并下载结果。

## 三个工具，三个可验证的结果

| 工具 | 适合谁 | 跑完样例能看到什么 |
| --- | --- | --- |
| **电商退款对账** | 负责订单和结算的商家运营 | 订单 A2 预计结算 70 元，实际结算 65 元；可以从结果定位到对应输入行。查看[退款对账样例](refund-reconciliation/sample.json)。 |
| **AI 客服回归体检** | 给多家客户维护客服机器人的交付团队 | 新版把 30 天退货期改成 14 天，工作台会标记对应案例，并指出受影响的客户。查看[客服回归样例](ai-support-regression/sample.json)。 |
| **工业视觉复盘** | 维护产线质检模型的工程师 | 夜班样例里两个真实缺陷漏掉了一个，结果列出漏检率和对应图片名。查看[工业视觉样例](vision-error-review/sample.json)。 |

## 用自己的数据试

从上表复制对应样例的 JSON 结构，在工作台上传，或通过命令行传入文件。分析由本机 Node.js 服务执行。

```sh
node refund-reconciliation/index.mjs ./orders.json
node ai-support-regression/index.mjs ./support-cases.json
node vision-error-review/index.mjs ./inspection-records.json
```

- **对账**按订单号汇总，金额用整数分。预期结算按订单金额减退款计算，平台费用、补贴和汇率需按实际账单规则补充。
- **客服评测**比较已有的新旧回答，通过必含和禁用短语判定结果。
- **视觉复盘**汇总已有的二分类标签与预测。支持通过图片字段定位样本；分母为零时，对应比率返回 `null`。

## 这些原型想验证什么？

这个仓库记录一个算法工程师对三个创业方向的尝试。每个原型都围绕一件可以拿给用户看的交付物设计：**结算异常清单、客服回归报告、质检误检复盘结果**。当前版本适合拿脱敏样例跑一遍，看看哪份结果能替代你现在手工做的一步。

如果有一个方向值得你继续关注，欢迎 Star。反馈时，欢迎带上一个你实际遇到的场景：你现在怎么处理、哪一步最花时间、你需要结果长什么样。
